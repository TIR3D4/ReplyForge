# نصب ReplyForge 1.2.0rc1

این نسخه کاندید نصب و پذیرش مرحله‌ای است. آزمون‌های خودکار جای آزمون واقعی تلگرام، مدل و پنل‌های شما را نمی‌گیرند. [چک‌لیست تحویل](RELEASE_1_2_CHECKLIST.md) و [آزمون پذیرش](SMOKE_TEST.md) را پیش از فعال‌کردن پاسخ خودکار بخوانید.

## نصب تازه

پیش‌نیاز: VPS لینوکسی، Docker Engine و Compose v2، Python 3.11 یا جدیدتر، Git، دامنه متصل به VPS، پراکسی HTTPS، حساب Telegram Business و ربات مجاز. ظرفیت سرور باید با بار واقعی سنجیده شود؛ فقط یک worker اجرا کنید.

```sh
git clone --branch development/installable-v1.2 https://github.com/TIR3D4/ReplyForge.git
cd ReplyForge
python3 scripts/install.py --preset azadbird
```

برای کسب‌وکار عمومی `--preset generic` بگذارید. ابزار نصب توکن ربات، دامنه، نام و رمز مدیر را به‌صورت تعاملی می‌گیرد و رازهای مستقل می‌سازد. فایل `.env` موجود را بازنویسی نمی‌کند. هیچ راز یا لینک اشتراکی را در GitHub یا گزارش عمومی وارد نکنید. در نصب موجود، قبل از تأیید `INSTALL` بکاپ و بازیابی آزمایشی لازم است.

بستهٔ قابل نصب نیز در artifact با نام `ReplyForge-1.2.0rc1-installation` در اجرای موفق Actions قرار دارد. ZIP داخل آن همراه checksum و manifest است؛ پس از استخراج، همان دستور نصب را اجرا کنید. برای بازتولید دقیق، SHA اجرای موفق را ثبت کنید؛ نام شاخه ثابت‌بودن محتوا را تضمین نمی‌کند.

## HTTPS و راه‌اندازی تلگرام

برنامه فقط روی `127.0.0.1:8080` منتشر می‌شود. نمونهٔ Caddy برای دامنهٔ خودتان:

```caddy
support.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8080
}
```

پورت‌های لازم برای صدور گواهی و HTTPS را طبق تنظیمات پراکسی باز کنید. دیتابیس را عمومی نکنید. مسیر `/admin` را ترجیحاً پشت VPN، محدودیت IP یا پراکسی هویت نگه دارید؛ وبهوک تلگرام باید قابل دسترسی بماند. ورود فعلاً HTTP Basic با محدودیت تلاش ورود است، نه MFA داخلی.

```sh
docker compose ps
docker compose logs --tail=100 init api worker
docker compose exec -T api replyforge doctor
curl --fail http://127.0.0.1:8080/readyz
# فقط پس از سالم‌بودن HTTPS دامنه:
docker compose exec -T api replyforge set-webhook
docker compose exec -T api replyforge webhook-info
```

ربات را در تنظیمات Business حساب فعلی متصل کنید و مجوز چت‌های آزمایشی را بدهید. ورود به `https://YOUR_DOMAIN/admin` با اطلاعات مدیر انجام می‌شود. حالت پیش‌فرض `AUTO_REPLY_ENABLED=false` است: ابتدا دریافت پیام، پاسخ انسانی، واگذاری و توقف اضطراری را آزمایش کنید، سپس پاسخ خودکار را روشن کنید.

## مدل و بودجه

نشانی سرویس سازگار و کلید AI در `.env` تنظیم می‌شوند. مدل اصلی/جایگزین، سقف خروجی، تعداد درخواست و بودجه روزانه از `/admin/agent` قابل تنظیم‌اند. قیمت ورودی و خروجی به دلار برای یک میلیون توکن را با مقدار پوشش‌دهندهٔ گران‌ترین مدل اصلی/جایگزین وارد کنید. قیمت صفر یا نامشخص، درخواست مدل را متوقف می‌کند. گزارش رزرو/مصرف در `/admin/system` است.

دفتر بودجه در تراکنشی مستقل ثبت می‌شود؛ timeout رزرو را آزاد نمی‌کند. اعداد مبتنی بر نرخ تنظیم‌شده هستند، نه صورتحساب قطعی ارائه‌دهنده. برای صوت، تصویر، هزینه‌های جانبی و نرخ نامعتبر، سقف واقعی هزینه را در حساب ارائه‌دهنده نیز فعال کنید. استفادهٔ عملی AI همراه پردازش گفتگو به PostgreSQL نیاز دارد؛ SQLite برای توسعه است و در تداخل نوشتن، درخواست مدل را محافظه‌کارانه متوقف می‌کند.

## AzadBird و پنل‌ها

Marzban برای اشتراک نامحدود و PasarGuard برای تونل، آداپتورهای مستقل فقط‌خواندنی دارند. نشانی و رازهای پنل را خصوصی در `.env` تنظیم کنید. نگاشت اشتراک باید با کاتالوگ معتبر یا API داخلی ثبت شود؛ لینک دلخواه مشتری دانلود نمی‌شود.

```sh
docker compose exec -T api replyforge sync-subscriptions --provider both --limit 2000
# پس از تأیید نسخه‌ها و محدودیت درخواست پنل‌ها:
docker compose --profile vpn up -d catalog
```

نسخه‌های پنل نصب‌شده را آزمایش و در صورت نیاز با `MARZBAN_EXPECTED_VERSION` و `PASARGUARD_EXPECTED_VERSION` محدود کنید. تأیید پرداخت همچنان وظیفهٔ اپراتور/سامانهٔ معتبر مالی است؛ عکس رسید کافی نیست.

## Insight

```sh
docker compose --profile insight up -d --build insight
```

از `/admin/insight` خروجی JSON تلگرام یا ZIP محدود را وارد کنید و شناسه فرستندهٔ اپراتورها را مشخص کنید. انتخاب ۱۰۰، ۲۰۰، ۵۰۰ یا تعداد سفارشی وجود دارد. واردسازی اولیه محلی و همگام است؛ تحلیل اختیاری مدل در صف پایدار جداگانه انجام می‌شود.

برای تصویر مرتبط، آن را از فایل‌های خروجی روی دستگاه خودتان انتخاب کنید، نام‌ها، لینک‌ها، QR و اطلاعات حساس را روی بوم بپوشانید و تأیید ارسال بدهید. فایل اصلی از فرم تصویر ارسال نمی‌شود؛ PNG بازبینی‌شده ارسال می‌شود. این پوشاندن **دستی** است و کشف خودکار همهٔ اطلاعات حساس نیست. تصاویر آنلاین مشتری در صورت فعال‌کردن vision مسیر دیگری دارند و خودکار پوشانده نمی‌شوند. پیشنهاد FAQ یا گردش‌کار تنها با تأیید مدیر منتشر می‌شود. نتیجهٔ تاریخی «تأییدنشده» باقی می‌ماند.

## بکاپ، ارتقا و بازگشت

```sh
python3 scripts/backup.py
```

اسکریپت، dump با مجوز محدود و checksum در `backups/` می‌سازد. بکاپ دیتابیس جای بکاپ خصوصی `.env`، تنظیمات و نسخهٔ image را نمی‌گیرد. نسخهٔ رمزگذاری‌شده را خارج سرور نگه دارید. مثال cron روزانه، پس از جایگزینی مسیر نصب و تحت کاربری که دسترسی Docker دارد:

```cron
15 3 * * * /usr/bin/python3 /opt/ReplyForge/scripts/backup.py >> /opt/ReplyForge/backups.log 2>&1
```

این زمان‌بندی باید روی VPS نصب شود؛ اکنون روی سرور شما فعال نشده است. فضای دیسک، موفقیت اجرا و سیاست حذف/رمزگذاری بکاپ‌ها را پایش کنید. dump حاوی داده حساس است.

برای ارتقا: توقف پاسخ خودکار، پوشش انسانی، توقف `api worker` و در صورت فعال‌بودن `insight catalog`، تهیه و بازیابی آزمایشی بکاپ در دیتابیس جداگانه، ثبت SHA/image قبلی، انتخاب SHA بررسی‌شده با CI سبز، build، اجرای `docker compose run --rm init` و راه‌اندازی دوباره. سر migration این نسخه `0011_release_runtime` است. اگر شکست خورد، دیتابیس خراب را برای بررسی حفظ کنید و نسخهٔ برنامه و بکاپ متناظر را در دیتابیس **جدید** بازیابی کنید. از `down --volumes`، downgrade خودکار و بازیابی آزمایشی روی دیتابیس مشتری استفاده نکنید.

راهنمای جزئیات: [عملیات و استقرار](DEPLOYMENT.md)، [بازیابی و عیب‌یابی](UPGRADE_READINESS_BRANCH.md). ابزار `scripts/deployment_smoke.py` فقط محیط مستقل آزمایشی می‌سازد و بکاپ مشتری را آزمایش نمی‌کند.
