# راه‌اندازی ReplyForge برای کسب‌وکارهای فارسی

ReplyForge یک سامانه پشتیبانی مستقل است که از طریق اتصال رسمی Telegram Business به همان اکانت پشتیبانی شما متصل می‌شود. مشتری لازم نیست به ربات دیگری پیام بدهد.

## امکانات اصلی

- منوی شیشه‌ای قابل تنظیم با ویرایش پیام قبلی
- درک اولیه متن آزاد با AI اختیاری
- گردش‌کارهای چندمرحله‌ای، پرسیدن اطلاعات و دریافت تصویر
- صف درخواست اپراتور، مدیریت دستی و توقف پاسخ هوشمند (در صورت تنظیم چت اعلان، تصویر رسید نیز برای اپراتورها ارسال می‌شود)
- داشبورد وب، دانشنامه تأییدشده، گزارش ارسال نامطمئن
- اتصال فقط‌خواندنی به Marzban برای سرویس‌های نامحدود و Pasarguard برای سرویس‌های تانل

## استفاده برای پرنده آزاد

در فایل .env مقدار BUSINESS_CONFIG را به examples/azadbird.yaml تغییر بدهید. اطلاعات پنل‌ها را **فقط در فایل .env سرور** وارد کنید. سپس سرویس‌ها را از نو راه‌اندازی کنید.

پیام مشتری: «سرویسم وصل نمیشه»
1. ایجنت لینک اشتراک را درخواست می‌کند.
2. لینک با فهرست امن اشتراک‌های ثبت‌شده تطبیق داده می‌شود.
3. با API پنل واقعی، حجم و انقضا بررسی می‌شود.
4. اگر اشتراک فعال باشد، دستگاه و نرم‌افزار پرسیده می‌شود.
5. بروزرسانی اشتراک و تست اینترنت دیگر پیشنهاد می‌شود.
6. اگر مشکل پابرجا بود، تیکت انسانی ثبت می‌شود.

اگر لینک مشتری قبلاً در سامانه ثبت نشده باشد، بدون حدس‌زدن نام کاربری یا افشای اطلاعات پنل، به اپراتور ارجاع داده می‌شود.

پیام مشتری: «رسیدم تأیید نشده»
- زمان پرداخت را از بین گزینه‌ها انتخاب می‌کند.
- تصویر رسید را ارسال می‌کند. برای تأخیر بالای ۱۵ دقیقه، در صورت امکان تصویر پیامک برداشت هم درخواست می‌شود و هر دو مدرک به اپراتور دارای دسترسی ارسال می‌شوند.
- تیکت انسانی ثبت می‌شود؛ تصویر رسید هیچ‌وقت تأیید بانکی محسوب نمی‌شود.

## نصب

مراحل کامل و دستورات در README اصلی و docs/DEPLOYMENT.md آمده است. دسترسی مدیریتی وب را فقط روی HTTPS و در صورت امکان پشت VPN یا محدودیت IP منتشر کنید. برای هر کسب‌وکار جداگانه یک استقرار بسازید. کلید پنل‌ها نباید داخل فایل‌های عمومی GitHub باشند.

## شخصی‌سازی

محتوای منو و تمام مراحل داخل YAML است و نیاز به دست‌زدن به کد ندارد. پاسخ‌های مصوب را می‌توان از پنل مدیریت اضافه کرد. برای دریافت نام کاربری پنل از یک لینک اشتراک باید لینک قبلاً به حساب مشخصی مرتبط شده باشد؛ این ارتباط به‌صورت HMAC ذخیره می‌شود.

## راه‌اندازی مرحله‌ای

نسخه جدید برای جلوگیری از پاسخ ناخواسته با حالت مشاهده (AUTO_REPLY_ENABLED=false) آغاز می‌شود.

1. روی سرور python3 scripts/setup.py --preset azadbird اجرا و اطلاعات پنل‌ها را در فایل خصوصی .env ثبت کنید.
2. docker compose up -d --build را اجرا کنید.
3. دامنه HTTPS را تنظیم و docker compose exec api replyforge set-webhook را اجرا کنید.
4. ربات را از بخش Telegram Business/Secretary به اکانت پشتیبانی وصل کنید.
5. از یک اکانت آزمایشی پیام بدهید؛ باید ثبت شود اما AI هنوز پاسخ ندهد.
6. از پنل مدیریت یک پاسخ انسانی آزمایشی بفرستید و تحویل آن را بررسی کنید.
7. مسیر /readyz را بررسی کنید تا پردازشگر نیز آنلاین باشد.
8. سپس در داشبورد «فعال‌کردن پاسخگویی» را انتخاب کنید. هر لحظه می‌توان AI را متوقف کرد.

## همگام‌سازی اشتراک‌ها

برای واردکردن فهرست لینک‌های مرزبان و PasarGuard، بعد از تنظیم APIهای مجاز از دستور زیر استفاده کنید:

    docker compose exec api replyforge sync-subscriptions --provider both --limit 2000

بجای both می‌توان marzban یا pasarguard را انتخاب کرد. فقط اطلاعات کاربران خوانده می‌شود. توکن کامل اشتراک در دیتابیس ذخیره نمی‌شود؛ یک اثرانگشت امن HMAC ذخیره خواهد شد. لینک‌های دامنه Relay با توکن یکسان هم قابل تطبیق‌اند، اما تطبیق مبهم به اپراتور انسانی ارجاع می‌شود.

## پردازش اختیاری تصاویر و ویس

AI_VISION_ENABLED و AI_VOICE_ENABLED در نصب اولیه خاموش‌اند. فقط در صورت پذیرش الزامات حریم خصوصی و تنظیم AI_API_KEY آن‌ها را روشن کنید. عکس خطاها ممکن است خوانده شود؛ عکس رسید مالی برای مدل بینایی ارسال نمی‌شود. سقف حجم فایل و بودجه فراخوانی AI قابل تنظیم است.

## ارزیابی کیفیت و پایداری

مشتری می‌تواند حل‌شدن یا حل‌نشدن مشکل را تأیید کند؛ موارد ناموفق به اپراتور منتقل می‌شوند. پاسخ اپراتور در تاریخچه ثبت می‌شود. مسیر /readyz قطعی Worker را از کارکرد ظاهری API جدا می‌کند. پیش از استفاده عمومی، اتصال واقعی Telegram Business و نسخه پنل‌های خود را با مشتری تستی آزمایش کنید.
